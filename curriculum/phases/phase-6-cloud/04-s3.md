# Phase 6 — Chapter 4: S3 (Simple Storage Service)

---

## Chapter Overview

S3 is AWS's object storage service — infinitely scalable, 99.999999999% (11 nines) durability, available globally. It is the backbone of most AWS architectures: static website hosting, backups, data lakes, file uploads, CDN origin, and CI/CD artifact storage.

**Topics:**
- Objects, buckets, keys
- Storage classes (Standard, IA, Glacier)
- Access control (bucket policies, ACLs, presigned URLs)
- Static website hosting
- Versioning and lifecycle rules
- S3 Events and notifications
- Multipart upload for large files
- S3 Select and analytics

## Beginner Theory

### Core Concepts

```
Object:   Any file — text, images, videos, binaries. Up to 5 TB per object.
Key:      The object's name/path within a bucket (e.g., "images/photo.jpg")
          Objects are NOT organized in folders — keys just contain "/" in their name
Bucket:   Container for objects. Name is globally unique across all AWS accounts.
          Bucket names can be used as DNS names if hosting a static site.

URL format:
  Path-style (legacy):    https://s3.amazonaws.com/bucket-name/key
  Virtual-hosted-style:   https://bucket-name.s3.amazonaws.com/key

S3 is NOT a file system:
  - No directory structure (key contains "/" by convention only)
  - No random access or file patching — replace entire object
  - No locking (last write wins)
  - Strong read-after-write consistency (since 2020)
  
Key operations:
  PUT (upload), GET (download), DELETE, HEAD (metadata), COPY
  LIST (ListObjectsV2 — list objects by prefix)
```

### Storage Classes

```
S3 Standard:          Frequently accessed data. 99.99% availability.
                      Most expensive storage. No retrieval fee.

S3 Standard-IA:       Infrequently accessed but quick retrieval.
                      Lower storage cost, per-retrieval fee, 30-day min.
                      Best for: backups, DR copies

S3 One Zone-IA:       Like IA but stored in single AZ (95 nines durability).
                      20% cheaper than Standard-IA. Risk: AZ loss = data loss.
                      Best for: re-creatable data

S3 Glacier Instant:   Archive with ms retrieval. For quarterly-accessed data.
S3 Glacier Flexible:  Archive, minutes-to-hours retrieval, cheapest.
S3 Glacier Deep Archive: Archive, 12-hour retrieval, $0.00099/GB/mo.

S3 Intelligent-Tiering: Auto-moves objects between tiers based on access pattern.
                         No retrieval fee for frequent-to-infrequent transitions.
                         Small monitoring fee per object.
                         Best for: unknown or changing access patterns
```

## Basic Examples

### S3 with AWS CLI

```bash
# Create bucket
aws s3 mb s3://my-app-bucket-unique-name --region us-east-1

# Upload
aws s3 cp ./app/dist/index.html s3://my-app-bucket/index.html
aws s3 cp ./large-file.zip s3://my-app-bucket/backups/large-file.zip

# Upload directory
aws s3 sync ./dist s3://my-app-bucket/static \
  --cache-control "max-age=31536000,immutable" \
  --exclude "*.html" \
  --include "*.html" --cache-control "no-cache"

# Download
aws s3 cp s3://my-app-bucket/backups/backup.tar.gz ./

# List
aws s3 ls s3://my-app-bucket/ --recursive --human-readable

# Delete
aws s3 rm s3://my-app-bucket/old-file.txt
aws s3 rm s3://my-app-bucket/backups/ --recursive

# Sync with delete (mirror local to S3)
aws s3 sync ./dist s3://my-app-bucket/ --delete
```

### S3 with Node.js SDK

```typescript
import {
  S3Client,
  PutObjectCommand,
  GetObjectCommand,
  DeleteObjectCommand,
  ListObjectsV2Command,
  CreateMultipartUploadCommand,
  UploadPartCommand,
  CompleteMultipartUploadCommand
} from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const s3 = new S3Client({ region: process.env.AWS_REGION });

const BUCKET = process.env.S3_BUCKET!;

// Upload object
export async function uploadFile(key: string, body: Buffer | Readable, contentType: string) {
  await s3.send(new PutObjectCommand({
    Bucket:      BUCKET,
    Key:         key,
    Body:        body,
    ContentType: contentType,
    ServerSideEncryption: "AES256"
  }));
  return `https://${BUCKET}.s3.amazonaws.com/${key}`;
}

// Download object
export async function downloadFile(key: string): Promise<Buffer> {
  const response = await s3.send(new GetObjectCommand({ Bucket: BUCKET, Key: key }));
  return Buffer.from(await response.Body!.transformToByteArray());
}

// Generate presigned URL (secure temporary access without credentials)
export async function getPresignedUrl(key: string, expiresInSeconds = 3600) {
  return getSignedUrl(
    s3,
    new GetObjectCommand({ Bucket: BUCKET, Key: key }),
    { expiresIn: expiresInSeconds }
  );
}

// Generate presigned upload URL (client uploads directly to S3 — no server bandwidth)
export async function getPresignedUploadUrl(key: string, contentType: string) {
  return getSignedUrl(
    s3,
    new PutObjectCommand({
      Bucket:      BUCKET,
      Key:         key,
      ContentType: contentType,
      ServerSideEncryption: "AES256"
    }),
    { expiresIn: 300 }  // 5 minutes
  );
}

// List objects by prefix
export async function listFiles(prefix: string) {
  const result = await s3.send(new ListObjectsV2Command({
    Bucket:    BUCKET,
    Prefix:    prefix,
    MaxKeys:   1000
  }));
  return result.Contents?.map(obj => ({
    key:          obj.Key!,
    size:         obj.Size!,
    lastModified: obj.LastModified!
  })) ?? [];
}

// Delete object
export async function deleteFile(key: string) {
  await s3.send(new DeleteObjectCommand({ Bucket: BUCKET, Key: key }));
}

// Upload large file with multipart (required for >5 GB, recommended for >100 MB)
import { Upload } from "@aws-sdk/lib-storage";
import fs from "fs";

export async function uploadLargeFile(key: string, filePath: string) {
  const upload = new Upload({
    client: s3,
    params: {
      Bucket:               BUCKET,
      Key:                  key,
      Body:                 fs.createReadStream(filePath),
      ServerSideEncryption: "AES256"
    },
    partSize: 10 * 1024 * 1024,  // 10 MB parts
    queueSize: 4                  // 4 concurrent uploads
  });

  upload.on("httpUploadProgress", progress => {
    console.log(`Uploaded: ${progress.loaded} / ${progress.total} bytes`);
  });

  await upload.done();
}
```

## Intermediate Concepts

### Bucket Policy and Presigned URLs

```hcl
# Terraform: S3 bucket with policy
resource "aws_s3_bucket" "app" {
  bucket = "myapp-assets-${var.environment}"
}

# Block all public access (default on, recommended)
resource "aws_s3_bucket_public_access_block" "app" {
  bucket = aws_s3_bucket.app.id

  block_public_acls       = true
  block_public_policy     = true
  ignore_public_acls      = true
  restrict_public_buckets = true
}

# Enable versioning
resource "aws_s3_bucket_versioning" "app" {
  bucket = aws_s3_bucket.app.id
  versioning_configuration { status = "Enabled" }
}

# Enable server-side encryption
resource "aws_s3_bucket_server_side_encryption_configuration" "app" {
  bucket = aws_s3_bucket.app.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "AES256"
    }
    bucket_key_enabled = true
  }
}

# Lifecycle policy: move old versions to IA then Glacier, delete after 1 year
resource "aws_s3_bucket_lifecycle_configuration" "app" {
  bucket = aws_s3_bucket.app.id

  rule {
    id     = "move-old-versions"
    status = "Enabled"

    noncurrent_version_transition {
      noncurrent_days = 30
      storage_class   = "STANDARD_IA"
    }

    noncurrent_version_transition {
      noncurrent_days = 90
      storage_class   = "GLACIER"
    }

    noncurrent_version_expiration {
      noncurrent_days = 365
    }
  }

  rule {
    id     = "delete-incomplete-multipart"
    status = "Enabled"

    abort_incomplete_multipart_upload {
      days_after_initiation = 7
    }
  }
}

# Bucket policy: only allow access from CloudFront OAC
resource "aws_s3_bucket_policy" "app" {
  bucket = aws_s3_bucket.app.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid    = "AllowCloudFrontServicePrincipal"
      Effect = "Allow"
      Principal = {
        Service = "cloudfront.amazonaws.com"
      }
      Action   = "s3:GetObject"
      Resource = "${aws_s3_bucket.app.arn}/*"
      Condition = {
        StringEquals = {
          "AWS:SourceArn" = aws_cloudfront_distribution.main.arn
        }
      }
    }]
  })
}
```

### S3 Event Notifications

```hcl
# Trigger Lambda on object upload
resource "aws_s3_bucket_notification" "uploads" {
  bucket = aws_s3_bucket.app.id

  lambda_function {
    lambda_function_arn = aws_lambda_function.process_upload.arn
    events              = ["s3:ObjectCreated:*"]
    filter_prefix       = "uploads/"
    filter_suffix       = ".jpg"
  }

  # Also send to SQS for other events
  queue {
    queue_arn     = aws_sqs_queue.s3_events.arn
    events        = ["s3:ObjectRemoved:*"]
  }
}

# Allow S3 to invoke Lambda
resource "aws_lambda_permission" "s3_invoke" {
  statement_id  = "AllowS3Invoke"
  action        = "lambda:InvokeFunction"
  function_name = aws_lambda_function.process_upload.function_name
  principal     = "s3.amazonaws.com"
  source_arn    = aws_s3_bucket.app.arn
}
```

### Static Website Hosting

S3 can serve a static site (HTML/CSS/JS, or a built React/Vue app) directly, with no server to manage — you're paying only for storage and bandwidth, and S3's durability/availability become the site's durability/availability.

```hcl
resource "aws_s3_bucket" "website" {
  bucket = "myapp-static-site"
}

resource "aws_s3_bucket_website_configuration" "website" {
  bucket = aws_s3_bucket.website.id

  index_document { suffix = "index.html" }
  error_document { key    = "404.html" }
}

# Static sites need PUBLIC read access (this is one of the few legitimate
# cases to allow it — normally you'd block public access, as shown earlier)
resource "aws_s3_bucket_public_access_block" "website" {
  bucket                  = aws_s3_bucket.website.id
  block_public_acls       = false
  block_public_policy     = false
  ignore_public_acls      = false
  restrict_public_buckets = false
}

resource "aws_s3_bucket_policy" "website" {
  bucket = aws_s3_bucket.website.id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "PublicReadGetObject"
      Effect    = "Allow"
      Principal = "*"
      Action    = "s3:GetObject"
      Resource  = "${aws_s3_bucket.website.arn}/*"
    }]
  })
}
```

```bash
# Deploy a built frontend app to the site
aws s3 sync ./dist s3://myapp-static-site/ --delete

# The site is now live at the S3 website endpoint:
# http://myapp-static-site.s3-website-us-east-1.amazonaws.com
```

In production, you almost never point users directly at the S3 website endpoint — instead you put CloudFront in front of it (covered in the CloudFront chapter) for HTTPS, a custom domain, and edge caching, and lock the bucket back down to CloudFront-only access using an Origin Access Control instead of the fully public policy shown above.

### S3 Select

S3 Select lets you run a SQL-like query against a CSV, JSON, or Parquet object and get back only the matching rows/columns — without downloading and parsing the entire file yourself. For a 2 GB CSV where you only need 3 columns from rows matching one condition, this can cut both transfer time and cost dramatically.

```typescript
import { S3Client, SelectObjectContentCommand } from "@aws-sdk/client-s3";

const s3 = new S3Client({ region: "us-east-1" });

const response = await s3.send(new SelectObjectContentCommand({
  Bucket: "myapp-data-lake",
  Key:    "orders/2025-01-15.csv",
  ExpressionType: "SQL",
  Expression: "SELECT s.order_id, s.total FROM s3object s WHERE s.status = 'completed'",
  InputSerialization:  { CSV: { FileHeaderInfo: "USE" } },
  OutputSerialization: { CSV: {} }
}));

// Results arrive as a stream of "Records" events
for await (const event of response.Payload!) {
  if (event.Records) {
    process.stdout.write(Buffer.from(event.Records.Payload!).toString());
  }
}
```

For anything beyond simple filtering — joins across files, aggregations over an entire data lake — the natural next step up is AWS Athena, which runs full SQL over S3 data using the same underlying idea but with the power of Presto behind it.

## Interview Preparation

**Q1: How does S3 achieve 11 nines of durability?**
A: S3 Standard stores data redundantly across a minimum of three Availability Zones in a region. Each object is checksummed and stored with redundant copies. AWS continuously monitors data integrity and automatically repairs any detected bit rot or disk failure. The 11 nines (99.999999999%) means losing one object out of 10 billion per year. This is achieved through: geographic redundancy (3+ AZs), erasure coding, continuous integrity checking, and automated repair. S3 One Zone-IA breaks this model by storing in a single AZ (95 nines) — accept the tradeoff only for re-creatable or derived data.

**Q2: What is a presigned URL and what are its use cases?**
A: A presigned URL is a temporary URL generated server-side (using AWS credentials) that grants time-limited access to a specific S3 object — without requiring the client to have AWS credentials. The URL embeds the signature and expiry time. Upload presigned URL: client uploads directly to S3 (bypasses your server — no bandwidth cost). Download presigned URL: grants read access to a private object for a specific duration (e.g., 1 hour). Uses: secure file downloads in SaaS apps (invoice PDFs), direct browser-to-S3 uploads (image upload without server relay), sharing private documents temporarily. Never expose private objects publicly — use presigned URLs with short expiry.

**Q3: What is S3 Versioning and why should you enable it?**
A: Versioning keeps multiple versions of an object — when you overwrite or delete, the old version is preserved. S3 retains a delete marker instead of deleting. Benefits: protection against accidental deletion or overwrite, enable point-in-time recovery, required for S3 Cross-Region Replication. Trade-off: storage cost increases (all versions are stored). Manage cost with lifecycle rules: transition old versions to Glacier after 30 days, delete after 1 year. Always enable versioning on production buckets. To hard-delete all versions: must delete each version individually. MFA Delete (additional setting) requires MFA to permanently delete versions — extra protection for critical data.

## Cheat Sheet

```bash
# S3 CLI
aws s3 mb s3://bucket-name
aws s3 cp file.txt s3://bucket/key
aws s3 cp s3://bucket/key ./
aws s3 sync ./dir s3://bucket/prefix/ --delete
aws s3 ls s3://bucket/ --recursive
aws s3 rm s3://bucket/key
aws s3 presign s3://bucket/key --expires-in 3600   # presigned URL

# S3 low-level API
aws s3api put-object --bucket mybucket --key key --body file.txt --server-side-encryption AES256
aws s3api get-object --bucket mybucket --key key output.txt
aws s3api list-object-versions --bucket mybucket --prefix key
aws s3api delete-object --bucket mybucket --key key --version-id <version>
```

```typescript
// Key patterns
```
