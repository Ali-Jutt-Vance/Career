# Career Book — Backend Mastery, 0 to Hired

**One book. One app. One deadline: 11 September 2027.**

Everything in this folder is a single system with a single purpose — a signed offer as a
**backend engineer** at a top-tier Pakistani company, on Node, NestJS, TypeScript,
PostgreSQL, MongoDB, Redis, Docker and AWS, at a minimum of **PKR 250,000/month**.

---

## Open it

Double-click **Career Book** on your Desktop.

No icon yet (new PC, fresh clone)? Double-click **`Install Desktop Icon.cmd`** in this
folder once. It needs Chrome, Edge or Brave.

It opens in a chromeless window with its own icon and taskbar entry — no address bar, no
tabs. It has its own browser profile, so your progress is never cleared by normal
browsing. The app opens on **today's plan** every time.

Zero to backend expert, in the specific shape a three-year backend developer is hired at.

chapters covering SQL *and* NoSQL, all 16 DevOps chapters including Jenkins, 15 AWS

scheduled, and held to a depth target.

## The schedule

| | Mon–Fri | Saturday | Sunday |
|---|---|---|---|
| **Every week, all 50** | **2h** | **4h** | **OFF** |

**Fourteen hours a week, held for fifty straight weeks.** One budget, no ramp, no second
regime. Sunday carries no tasks and the streak counter treats it as neutral, so resting
never breaks it.

**Weekday (2h)** — `05:00–06:30` deep work (90m) · `13:00–13:30` job hunt or English (30m)
**Saturday (4h)** — `08:00–10:00` deep build (120m) · `10:30–11:30` drill (60m) · `12:00–13:00` review + apply (60m)

The dawn block is what makes this work while employed. Evening study is the first thing
life cancels, which is why none is scheduled. The dawn block carries study on some days
and building on others — the day's spec says which. Do not merge them.

## The rule that makes it work

**For the first eighteen weeks, no AI writes code for you.** Not a line.

Documentation is allowed. This book is allowed. Asking an AI to *explain a concept* is
allowed **after** twenty minutes of genuine attempt. Generated code is not.

On **1 February 2027** it comes back permanently, under one clause: *you must be able to
explain, unaided, every line of code in your repository.* Reviewer and teacher, never
author. The Saturday drill stays AI-free for all fifty weeks, because interviews are.

Three years of outsourced thinking is the hole this plan digs you out of, and you cannot
dig out of it with a shovel that digs for you. Phase 0 Chapter 4 is the argument.

## The eight rules

1. **The dawn block is untouchable.** 05:00–06:30, every working day.
2. **No AI writes code until 1 February 2027.** Documentation yes. Generated code no.
3. **Commit publicly every day.** A day with no commit did not happen.
4. **Twenty minutes before you look anything up.** Most of the time you solve it in eight.
5. **Start applying before you feel ready.** 26 October, regardless.
6. **Miss one day, fine. Miss two, diagnose.** Never catch up — resume on today.
7. **Milestones are pass or fail.** "Mostly" is a no.
8. **Ignore everything marked LATER.** If it is not in the week you are on, it is not
   your problem yet.

When you fall behind: **cut breadth, preserve depth.** Drop the reference reading, keep
the building and the job hunt.

The risk in a sixteen-week plan is burnout. The risk in a fifty-week plan is drift —
weeks that pass without anything shipping. That is what the weekly milestone is for, and
why it is pass or fail.

## Rebuilding

Everything is generated. Edit the sources, then rebuild.

```bash
cd curriculum

npm run build          # plan + reader + smoke test    (~12s)
npm run build:all      # + PDF + icon + shortcut
npm run pdf            # include the PDF render        (slow)
npm run plan           # regenerate the 350-day plan only
npm run test           # smoke-test the reader in a real browser
npm run install:app    # recreate the Desktop shortcut
node plan/audit.js     # chapter-depth audit → EXPANSION-STATUS.md
```

### Where things live

```
curriculum/
  phases/                     the book — one folder per phase, markdown chapters
  plan/
    plan-data.js              THE PLAN — 50 weeks, authored day by day, plus CORE
    build-plan.js             expands it into data/plan.json + Phase 12 chapters
    audit.js                  chapter-depth audit (CORE only)
    smoke-test.js             drives the built app in a real browser
  scripts/reader.js           the reader app
  styles/                     themes
  app/                        icon, installer, and the app's browser profile
  output/index.html           the built app  ← the shortcut points here
  compile.js                  markdown → reader + PDF
  build.js                    one-command pipeline
  EXPANSION-STATUS.md         chapter depth tracker
```

**To change the plan**, edit `plan/plan-data.js` and run `npm run build`.

**To change what counts as core**, edit the `CORE` list in the same file. A chapter
scheduled in a week must be in `CORE` or the build fails — deliberately, so breadth
cannot creep back one week at a time.

The build **asserts** on every run: 350 continuous days starting on a Monday, 50 Sundays
off with zero tasks, weekdays exactly 120 minutes and Saturdays exactly 240, every week at
exactly 14h, every week carrying a review, applications opening on Monday 19 October with
a quota from that week on and none before, every anchor inside the plan, and every chapter
reference resolving to a real file that is in `CORE`. If any of that breaks, the build
fails. Browser smoke checks then drive the built app for real.

The application count is **data** (`APPLY_QUOTA`), rendered into the book and the app.
Rewording a task can never silently change the plan.

## Chapter depth

Core chapters are being expanded to a consistent beginner→mastery arc:

> Overview · Beginner Theory · Basic Examples · Intermediate · Advanced · Industry Usage ·
> Alternatives · Security · Performance · Debugging · **Interview Preparation** ·
> Practical Tasks · Projects · Self Assessment · Cheat Sheet

Depth bands: core interview chapters 6,000+ words · standard 5,000+ · support 2,500+.

**LATER chapters have no target.** They are reference material and the audit does not
count them as outstanding work. That is the point of the split: the TODO list should be
the work that gets you hired, and nothing else.

Expansion order follows the **daily plan order**, so material is ready ahead of where you
are. Run `node plan/audit.js` for current status — it rewrites the table in
`EXPANSION-STATUS.md` and prints what is next.

**Status:** most Core chapters are still below their depth target. The two that did not
exist at all — Jenkins and Testing — have been written. The database block (W14–W22) and
the NestJS block (W23–W29) are the highest-value expansion targets and the shallowest
parts of the book.
